# KAF-001 기획서

- 작업 ID: `KAF-001`
- 기획서 버전: `1.1`
- 상태: Builder 구현 기준
- 대상 저장소: `MyungRag/KAF`
- 작성일: `2026-11-10`

## 1. 목표

여행자가 출발지와 여행 가능 조건을 입력하면 목적지를 먼저 고정하지 않고, 조건에 맞는 목적지와 항공편을 가격 기회가 좋은 순서로 찾는다. 각 결과에서 현재 총액을 최근 365일 가격 이력과 비교해 지금 구매할 만한지 판단할 수 있게 한다.

핵심 질문은 다음과 같다.

> 현재 조건에서 갈 수 있는 곳 중, 지금 가격 기회가 가장 좋은 목적지는 어디인가?

## 2. 사용자와 기본 흐름

주 사용자는 대한민국에서 출발하는 여행자다. 기본 통화는 KRW이고, 첫 구현은 성인 1명 왕복 일반석을 기준으로 한다. 화면과 안내 문구는 한국어로 제공한다. 이 기본값은 첫 구현의 단순화를 위한 가정이며, 별도 요구가 확인되면 버전을 올려 변경한다.

1. 사용자가 출발지, 출발 가능 기간, 여행 일수 범위, 직항 여부, 좌석 등급, 항공사 조건, 세금·유류할증료 포함 여부, 예산, 목적지 지역을 입력한다.
2. 검색은 목적지를 미리 고정하지 않고 조건에 맞는 목적지를 찾는다.
3. 목적지별 가장 저렴한 조건 일치 항공편을 가격 기회 순으로 보여준다.
4. 사용자는 지도와 목록에서 현재 가격 및 과거 가격 비교를 확인한다.

## 3. 검색 조건

- 출발지: 공항 또는 도시. 첫 화면 예시는 인천 출발이다.
- 출발 가능 날짜: 시작일과 종료일을 지정한다. 첫 단계의 검색 가능 범위는 오늘부터 365일 이내다.
- 여행 일수: 최소·최대 일수를 지정한다. 최소값은 1일 이상이며 최소값은 최대값보다 클 수 없다.
- 직항 여부: 직항만 또는 경유 포함을 선택한다.
- 좌석 등급: 일반석 또는 비즈니스석.
- 항공사 조건: 대한항공 또는 SkyTeam. 선택한 조건에 맞는 항공사만 결과에 포함한다.
- 총액 조건: 세금과 유류할증료를 포함한 KRW 총액을 사용한다. 최대 예산은 선택 입력이다.
- 목적지 범위: 국가·지역 또는 전체를 선택한다.

첫 구현에서는 성인 1명, 왕복 여정으로 제한한다. 편도, 인원 수 변경, 수하물·좌석 등 세부 부가서비스는 범위에 포함하지 않는다.

## 4. 목적지 탐색과 표시

- 첫 결과 화면은 지도와 목적지 목록을 함께 보여준다.
- 목적지별 최저 항공편 가격 기회를 우선순위로 정렬한다. 인기 순이나 목적지 이름 순을 기본 정렬로 사용하지 않는다.
- 지도 마커와 목록 항목은 같은 결과를 가리킨다. 한쪽에서 목적지를 선택하면 다른 쪽에서도 해당 결과가 식별되어야 한다.
- 결과에는 목적지, 출발·귀국 날짜, 항공사, 직항 여부, 좌석 등급, 세금 포함 총액, 가격 확인 시각, 데이터 출처를 표시한다.
- 목적지별 최근 365일 최저·평균·최고 가격, 현재 가격의 최저가 대비 차이, 가격 상태를 표시한다.
- 가격 이력이 충분하지 않으면 점수나 구매 권고를 만들지 않고 `데이터 축적 중`으로 표시한다.

## 5. 가격 비교와 점수

가격 비교는 조건이 서로 다른 운임을 섞지 않는다. 비교 그룹에는 출발지, 목적지, 왕복 여부, 여행 일수 범위, 좌석 등급, 항공사 조건, 직항 조건, 통화, 세금 포함 여부가 일치해야 한다. 비교 가능한 기록이 없거나 최근 365일 전체를 대표할 수 있는 이력이 없으면 가격 상태를 산출하지 않는다.

최근 365일 최저가를 `L`, 최근 365일 평균가를 `A`, 현재가를 `P`라 할 때 최저가 대비 차이는 `(P - L) / L × 100`으로 계산하고 소수점 첫째 자리까지 표시한다.

가격 상태는 다음 우선순위로 판정한다. 평균가가 최저가와 가까워 `최저가 +5%/+10%` 구간과 겹쳐도 결과가 하나로 정해지도록 한다.

1. 비교할 이력이 부족하면 `데이터 축적 중`이다.
2. 현재가 `P`가 최근 365일 최저가 `L` 이하이면 `적극 매수`다.
3. 현재가 `P`가 최근 365일 평균가 `A`보다 높으면 `기다림`이다. 이 규칙은 `L` 대비 5% 또는 10% 이내인지보다 우선한다.
4. 현재가 `P`가 평균가 `A`와 같으면 `보통`이다. 단, `P ≤ L`이면 2번 규칙을 먼저 적용한다.
5. `P ≤ 1.05 × L`이면 `매우 좋음`이다.
6. `P ≤ 1.10 × L`이면 `좋음`이다.
7. 그 밖에 `L < P < A`이면 `보통`이다.

| 조건 | 표시 |
|---|---|
| 비교할 이력이 부족하거나 없음 | 데이터 축적 중 |
| 현재가가 최근 365일 최저가 이하 | 🔥 적극 매수 |
| 현재가가 평균가 초과 | 기다림 |
| 현재가가 평균가와 같음(최저가보다 높음) | 보통 |
| 평균가보다 낮고 현재가가 최저가의 105% 이하 | 매우 좋음 |
| 평균가보다 낮고 현재가가 최저가의 105% 초과, 110% 이하 | 좋음 |
| 평균가보다 낮고 현재가가 최저가의 110% 초과 | 보통 |

샘플의 78만 원 현재가와 71만 원 최저가라면 최저가 대비 차이는 약 `+9.9%`다. 이 값은 문서의 계산 예시일 뿐 실제 운임을 뜻하지 않는다.

## 6. KAF-001 구현 범위

KAF-001은 검색 흐름·지도 화면·가격 비교 로직을 검증하는 **프로토타입**이다.

- 사용자가 검색 조건을 입력하고 검증할 수 있는 한국어 화면.
- 목적지를 미리 지정하지 않는 검색 결과 구조.
- 지도와 목록의 동기화.
- 최근 365일 가격 통계와 구매 매력도 계산.
- 외부 운임 제공자를 교체할 수 있는 데이터 제공자 경계(인터페이스).
- 외부 API 없이 재현 가능한 고정 데모 자료. 데모 운임과 데모 이력은 모두 `예시 데이터 · 실시간 아님`으로 눈에 띄게 표시한다.
- 로컬 설치·실행 방법 및 자체 검사 결과를 기록한다.

실시간 항공편 검색, 자동 가격 수집, 실제 가격 이력 구축, 예약·결제, 가격 알림은 KAF-001에 포함하지 않는다. 데모 자료를 실제 시세나 실제 1년 누적 이력으로 표시하지 않는다.

## 7. 후속 단계와 선행 조건

실제 항공편 검색과 지속적인 가격 이력 구축은 별도 작업에서 한다. 그 작업은 사용 가능한 데이터 제공자, 대한항공·SkyTeam 운임 범위, API 이용 조건, 검색 한도와 비용, 과거 운임 저장 허용 범위, API 접근 권한을 확인한 뒤 시작한다. API 키는 저장소나 브라우저 코드에 넣지 않고 서버 측 비밀 설정으로 관리한다.

현재 확인한 제공자 문서상 Skyscanner API는 파트너 신청과 승인이 있어야 접근할 수 있다. Amadeus Self-Service 문서에는 Delta 운임을 반환하지 않는 등 데이터 범위 제한이 적혀 있다. 따라서 KAF-001은 특정 제공자의 실시간 범위를 보장하지 않는다.

- [Skyscanner API 인증 및 접근](https://developers.skyscanner.net/docs/getting-started/authentication)
- [Amadeus Self-Service API FAQ 및 데이터 범위](https://admin.developers.amadeus.com/self-service/apis-docs/guides/developer-guides/faq/)

## 8. 완료 시 산출물

- 실행 가능한 KAF-001 프로토타입.
- 데모 데이터임을 분명히 표시한 지도·목록 화면.
- 검색 필터, 가격 통계, 점수 산출 로직.
- 설치·실행·검사 안내.
- 검토 대상 전체 커밋 SHA와 독립 검토용 전달서.

자세한 완료 판정은 `KAF-001_ACCEPTANCE.md` 버전 `1.1`을 따른다.
