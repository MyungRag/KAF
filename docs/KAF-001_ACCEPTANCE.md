# KAF-001 완료 기준

- 작업 ID: `KAF-001`
- 완료 기준 버전: `1.0`
- 적용 기획서: `docs/KAF-001_PLAN.md` 버전 `1.0`
- 대상 저장소: `MyungRag/KAF`

각 기준은 직접 실행하거나 코드·화면·로그에서 확인하고 근거를 남긴다. 미실행 기준은 통과가 아니라 미검증이다.

| ID | 완료 기준 | 확인 방법 |
|---|---|---|
| KAF-AC-01 | 한국어 화면에서 출발지, 출발 날짜 범위, 여행 일수 최소·최대, 직항 조건, 좌석 등급, 대한항공/SkyTeam 조건, 세금 포함 여부, 선택 예산, 목적지 지역을 입력할 수 있다. | 화면 확인 및 조건별 입력 |
| KAF-AC-02 | 출발일 범위는 시작일이 종료일보다 늦을 수 없고, 검색일은 오늘부터 365일 이내로 제한된다. 여행 일수는 양의 정수이며 최소값이 최대값보다 클 수 없다. 잘못된 입력은 원인을 알 수 있는 한국어 안내를 표시한다. | 유효·무효 경계값 입력 |
| KAF-AC-03 | 검색 결과는 출발지와 여행 조건을 만족하는 목적지를 찾으며, 목적지를 미리 지정하지 않아도 된다. 조건에 맞는 결과가 없을 때 빈 결과 상태를 설명한다. | 데모 제공자에 여러 목적지·무결과 사례 입력 |
| KAF-AC-04 | 지도와 목록에 동일한 목적지가 표시되고, 지도 마커와 목록을 선택하면 같은 상세 결과를 확인할 수 있다. | 지도·목록 상호작용 |
| KAF-AC-05 | 결과별로 목적지, 출발·귀국일, 항공사, 직항 여부, 좌석 등급, 세금 포함 KRW 총액, 데이터 출처와 확인 시각을 볼 수 있다. | 상세 결과 화면 확인 |
| KAF-AC-06 | 최근 365일 최저·평균·최고가와 현재가의 최저가 대비 비율이 표시된다. 계산은 `((현재가 - 최근 365일 최저가) / 최근 365일 최저가) × 100`이며 소수점 첫째 자리까지 일관된다. | 계산 예제와 경계값 비교 |
| KAF-AC-07 | 가격 상태가 기획서의 다섯 구간에 맞게 표시된다. 최저가와 같거나 낮으면 `🔥 적극 매수`, 최저가 대비 5% 이하는 `매우 좋음`, 5% 초과 10% 이하는 `좋음`, 10% 초과 평균가 이하는 `보통`, 평균가 초과는 `기다림`이다. | 각 구간의 바로 아래·경계·바로 위 값 검사 |
| KAF-AC-08 | 최근 365일 비교 이력이 없거나 충분하지 않으면 점수와 구매 권고를 표시하지 않고 `데이터 축적 중`으로 표시한다. 비교 조건이 다른 기록은 통계에 섞이지 않는다. | 이력 없음·일부 이력·조건 불일치 자료 검사 |
| KAF-AC-09 | 모든 고정 자료와 그에 따른 가격 통계는 화면에서 명확히 `예시 데이터 · 실시간 아님`으로 식별된다. 데모 자료를 실제 운임이나 실제 1년 누적 이력으로 설명하지 않는다. | 화면·문구·결과 설명 확인 |
| KAF-AC-10 | 데이터 제공자 연결부와 데모 제공자 구현이 분리되어 있어 이후 실제 제공자를 추가할 수 있고, 데모 모드에서 외부 API 키 없이 반복 실행할 수 있다. | 구조 검토 및 키 없이 실행 |
| KAF-AC-11 | 설치, 실행, 테스트 명령이 저장소 문서에 있고, Builder가 실행한 명령과 각 결과를 전달서에 기록한다. | 새 환경에서 문서대로 실행 |
| KAF-AC-12 | 프로젝트 검사와 가격 계산·조건 필터·입력 검증·이력 부족 처리를 확인하는 자동 검사가 통과한다. | 문서의 테스트 명령 실행 및 로그 확인 |
| KAF-AC-13 | 외부 API 키·토큰이 코드, 데모 자료, Git 이력에 포함되지 않는다. | 변경 파일과 설정 확인 |

## 이 작업에서 완료로 보지 않는 항목

- 실제 항공권 공급자 연결, 실시간 운임 보장.
- 실제 대한항공 또는 전체 SkyTeam 운임 범위.
- 자동 수집 스케줄러와 서비스 출시 후 365일의 누적 가격 DB.
- 예약, 결제, 사용자 계정, 가격 알림.

위 항목은 KAF-001에서 미구현 범위로 기록한다. 후속 실시간 데이터 연동 작업의 완료로 오인하지 않는다.

## 기준 조정

이 완료 기준과 다른 동작이 필요하면 구현 오류로 임의 수정하지 않는다. 먼저 기획서와 완료 기준의 새 버전을 확정하고 Builder가 새 버전을 기준으로 구현한다.
